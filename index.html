01

What's this?

A lot of web traffic today isn't people. It's scripts and bots clicking, buying and filling in forms. This hackathon is about that: software that acts on other software. It's the first one we've run, and it's built for CS and Cybersecurity students working together.

Computer Science

You lead the build

Crawlers, automation, back ends, front ends. You turn the brief into something that actually runs when the judge pokes at it.

Cybersecurity

You own half the score

Threat models, security checks, spotting traps, keeping user data safe. Every track has outcomes that only hold up if this part is done properly.

Track 1Build the agent
01

Testing Agent

Brief: Website QA bot

Software ships faster than anyone can test it. Give your agent a URL. It explores the site by itself and comes back with real problems, plus enough evidence for a developer to fix them.

It should check
  • Links, forms, checkout flow
  • Accessibility and performance
  • Security basics: headers, cookies, exposed files
Report

Overall grade and a score per area. For every finding: a screenshot, steps to reproduce and a suggested fix.

CSCrawler, browser automation, report UI
CyberSecurity checks, severity ratings, fix guidance
Think: Checkly, Mabl
Track 2Survive the agents
02

Agent-Proof Platform

Brief: Event ticketing

Build ticketing for campus events: sign up, browse, buy (max 4 per person per event), get a QR ticket that only works once, and give organisers a sales and check-in view. Then make sure bots can't break it.

Must hold up against
  • Forged or reused tickets
  • Buying over the limit, overselling
  • Viewing other people's orders
  • Price tampering, password guessing
CSBack end, database, purchase flow, QR tickets, front end
CyberThreat model, ticket signing, access control, rate limiting
Think: Platinumlist, DICE
Track 3Put the agent to work
03

Personal Task Agent

Pick brief A or B

An assistant that a sketchy page can fool is a liability. Build one that does a real chore across websites and can't be tricked along the way.

A · Subscription canceller
  • Hidden cancel buttons
  • "Pause instead?" detours
  • Forms asking for your card again
  • Fake confirmation pages
B · Job application agent
  • Scam listings
  • Forms asking for bank or passport details
  • Lookalike login pages
CSAutomation, task planning, error recovery, activity log
CyberSafe data handling, page verification, trap detection
Think: Rocket Money, Simplify
Heads upYou don't need paid AI credits. A browser automation bot (Playwright, Puppeteer, Selenium) counts as an agent, and free open-source tools are enough to score full marks.

09

FAQ

Q.01Who can join?
CS and Cybersecurity students. Every team of four has people from both. CS leads the build and Cyber is responsible for half of what gets scored.
Q.02I don't have a full team. Can I still register?
Yes. Sign up on your own or as a pair and we'll match you with people from the other discipline before the event.
Q.03Do I need paid AI tools or API keys?
No. A browser automation bot counts as an agent. Free, open-source tools are enough to get full marks.
Q.04Do we pick our track?
We'll confirm before kickoff whether teams choose their track or get one assigned so the tracks stay balanced. You'll hear from us in advance.
Q.05Can we start coding early?
Briefs and rubrics are released at kickoff and project code has to be written during the event. Learning your tools beforehand is encouraged.
Q.06How are winners picked?
Five required outcomes per track, each scored 0–3 live (50%), plus tech & code (20%), business value (10%), presentation (10%) and originality (10%). The full rubric is above.
Q.07What should I bring?
Laptop, charger, student ID. We'll handle food and Wi-Fi.
